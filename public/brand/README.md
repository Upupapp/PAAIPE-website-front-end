# Canonical PAAIPE brand assets

`npm run verify:brand` gates this directory. It fails if a canonical file
changes by a single byte, if a rendition is the wrong size or over budget, or
if an unexpected file appears in either directory.

## Renditions — `renditions/`

Generated by `npm run brand:renditions`. Each is a whole-file **proportional
downscale** of a canonical original: same artwork, same colours, same safe
space, fewer pixels. Nothing is redrawn, recoloured, cropped, traced or
regenerated, and no element is separated from the lockup.

| File | Size | Weight | Use |
| --- | --- | --- | --- |
| `paaipe-horizontal-600.png` | 600 × 209 | 80 KiB | Header and footer lockup (covers 300 CSS px at 2×) |
| `paaipe-square-512.png` | 512 × 512 | 154 KiB | Large badge, PWA icon |
| `paaipe-square-256.png` | 256 × 256 | 49 KiB | Compact badge |
| `paaipe-square-180.png` | 180 × 180 | 29 KiB | apple-touch-icon |

Why renditions exist: the canonical files total **1.8 MB**. Serving them into a
~40px header slot breaches the Tab 14 budgets (1 MiB initial transfer, 250 KiB
per image) on their own. All four renditions together are 324 KiB, and a page
using the header lockup plus a touch icon costs ~110 KiB.

Every scale factor is **exact**, verified by cross-multiplication in
`src/tests/brand.test.ts`, so no rendition distorts the artwork:

- horizontal 1800 × 627 → 600 × 209 (exactly ⅓)
- square 2000 × 2000 → any square size

`1200 × 418` (exactly ⅔) is the only other exact horizontal scale below 1:1. It
weighs 254 KiB, which breaches the image budget, and nothing needs it — so it is
deliberately **not** generated. Add it only with budget evidence.

## Measured geometry — the safe space is not symmetric

Measured from the alpha channel and recorded in `src/config/brand.ts`:

| | Artwork | Padding L / T / R / B |
| --- | --- | --- |
| Square | **1464 × 1747 — portrait, not square** | 269 / **81** / 267 / **172** |
| Horizontal | 1626 × 540 | **54** / 45 / **120** / 42 |

Consequences to design around:

- The square canvas holds **portrait** artwork sitting **91px above centre**. A
  badge or favicon that assumes the mark is centred in a 1:1 box will look
  low-heavy. Do not assume 1:1 artwork just because the canvas is square.
- The horizontal lockup sits **33px left of centre** — its right padding is more
  than double its left.

The artwork is deliberately **not** cropped to fix this: the master command
forbids cropping the logo. Any placement needing optical centring compensates in
CSS, using the recorded `padding` values. Tab 02 owns that compensation.

## Rules

- Do not optimise, resize by hand, recolour, crop or regenerate the canonical files.
- Do not add an alternate or recreated logo to either directory — the gate fails on it.
- Decorative map / network / node graphics belong in `public/media/`, never here.
