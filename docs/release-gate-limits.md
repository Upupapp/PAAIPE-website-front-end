## How to read the provenance labels

The findings read identically on the page and they are **not the same kind
of claim**. Every line below is labelled:

| Label                      | Means                                                                                    |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| **MEASURED** (`file:line`) | Read from source in this repository at the cited location. Check it by opening the file. |
| **INFERRED**               | A judgement about consequence or coupling. Not observed. Check it by arguing with it.    |

## G-01 · 1. Five of six detectors have been observed firing alongside a green row. B-7 has not.

The risk this addresses: a gate that evaluates its rows through a shared
accumulator can have one satisfied row suppress another, and every row would
still go red on a fully-empty state, so the defect never shows.

**MEASURED** (`src/config/release.ts:196-198`) — `evaluateInputs` is a single
`map` over `RELEASE_INPUTS` with no accumulator, no early return, no `break`,
and no shared results object. Each detector receives the same immutable `facts`
and returns independently.

**MEASURED** (`src/tests/release.test.ts:97-109`) — with all seven `PUBLIC_*`
destinations set, the supplied set is asserted **exactly equal** to
`['B-4', 'B-7']`. Because it is an exact-set assertion and not a subset check,
this test asserts that **B-5, B-6, B-8 and B-9 still fire while two rows are
green**. A subset assertion would read identically on the page and would prove
nothing; the strictness is the whole value of the test.

**MEASURED** (`src/tests/release.test.ts:111-118`) — with one destination
removed, B-4 is asserted `false` in the same result set where B-7 is asserted
`true`. That is **B-4 observed firing alongside a green row**.

**MEASURED** — no test asserts **B-7** false while any other row is true. The
tests that turn B-6 green (`src/tests/release.test.ts:130-133`) and B-9 green
(`:150-159`) assert only the flipped row and make no assertion about the rest.
The all-empty case (`:92-95`) asserts all six false, so no row is green in it.

**INFERRED** — the gap is small and cheap: one assertion in an existing test.
It is listed because "five of six" and "six of six" are different facts and the
document must say which.

## G-02 · 2. The B-5 and B-8 detectors have never been observed to succeed, and no test can reach their true branch

This is the inverse of the rule the gate was built on:

> **A detector proven only by FAILING is indistinguishable from a detector that
> cannot succeed.**

The failing direction feels safe, and therefore never gets examined.

**MEASURED** (`src/config/release.ts:126`) — B-5's detector is
`() => APPROVED_TYPEFACE !== null`. It takes **no `facts` argument**. It closes
over a module-level `const` that is `null` (`src/config/release.ts:48`).

**MEASURED** (`src/config/release.ts:150-154`) — B-8's detector closes over
`OPERATIONS`, `null` at `src/config/release.ts:68`.

**MEASURED** — every other detector (B-4, B-6, B-7, B-9) reads `facts`, which
tests inject freely. B-5 and B-8 read source constants, so the **only** ways to
reach their true branch are to edit `src/config/release.ts` or to mock the
module. Neither is done anywhere in the suite.

**MEASURED** (`src/tests/release.test.ts:171-176`) — the one test that names
them asserts `APPROVED_TYPEFACE` and `OPERATIONS` are `null`. It asserts the
false branch a second time. It is a correct and useful test; it is not evidence
the detector can succeed.

**MEASURED** (`src/config/release.ts:152-154`) — B-8 has a **second clause**,
an `.every()` over `Object.values(OPERATIONS)`, guarded by `OPERATIONS !== null`.
Because that guard is false today, **the `.every()` has never executed once**.

**INFERRED** — `[].every(...)` is `true`, so an `OPERATIONS` with no enumerable
properties would read as SUPPLIED. This is the same vacuous-pass shape the B-9
detector was explicitly hardened against with a length check
(`src/config/release.ts:164`, tested at `src/tests/release.test.ts:161-167`).
B-8 has no equivalent length check.

**MEASURED** (`src/config/release.ts:50-61`) — the `Operations` interface
requires five `string` fields, so `OPERATIONS = {}` does not typecheck. That is
the guard today.

**INFERRED** — a type is not a runtime check. A cast, a value loaded from JSON
or the environment, or a later widening of `Operations` to optional fields
removes that guard, and the clause underneath it still has no test.

**INFERRED — this is the cost, and it is why the item is worth writing down.**
`src/config/release.ts:17-22` promises that supplying an input turns its row
green with **no edit to the gate**. That promise is unproven for exactly the two
inputs whose supply _is_ an edit to that file. On the day B-5 or B-8 is finally
supplied, its detector runs for the first time in production conditions. A
defect there presents as _an input that was supplied and did not register_ —
which reads as a supply problem, gets debugged on the owner's side, and is
looked for in the wrong place.

**INFERRED** — the direction of failure is the safe one. A broken detector
leaves the row stuck BLOCKED, which cannot ship a false release. The residual is
diagnostic cost and a false accusation, not an unsafe release.

## G-03 · 3. The gate reads its facts from two different trees

**MEASURED** (`scripts/release-gate.mjs:203-207`) — the gate builds a detached
sibling worktree at the HEAD sha and runs every certified stage inside it
(`:211-239`).

**MEASURED** (`scripts/release-gate.mjs:255-259`) — B-6's fact,
`approvedMediaFiles`, is read from **the worktree**:
`join(worktree, 'public/media')`.

**MEASURED** (`scripts/release-gate.mjs:47-48`) — `evaluateInputs` and
`POLICIES` are `import`ed from `../src/config/release.ts` and
`../src/content/policies.ts`, which resolve against **ROOT**, the ordinary
checkout. So the B-5 and B-8 constants, the B-9 policy statuses (`:264`), and
`RELEASE_INPUTS` — the blocker list itself, and therefore the set of rows the
report prints — all come from ROOT, not from the certified sha.

**MEASURED** (`scripts/release-gate.mjs:129-140`) — this is safe today because
the gate refuses to run on a dirty tree, so ROOT and the worktree are identical
in content.

**MEASURED** (`scripts/release-gate.mjs:127`) — there is exactly one exemption
to that refusal: `docs/release-gate.md`, a single exact path, not a pattern. It
is the gate's own generated output and no detector reads it.

**INFERRED — the trigger, named.** The split stops being safe **the moment a
second dirty-tree exemption is added**. Exemptions are precisely the kind of
thing added later, by someone who does not know the first one was load-bearing.
If you are here to add one: an exempted path that any detector or any imported
config reads means the report can certify one sha and describe a different tree.
Either keep every exemption to files no detector reads, or move the imports at
`scripts/release-gate.mjs:47-48` into the worktree first.

**Recorded as a latent defect with its trigger, not as a note.** It is not a
bug today.

## G-06 · 5. The report asserts "every quality gate passed" from the owner-input count alone, and can contradict its own stage table

This is the same defect class as finding 4 and the note above it, in its
strongest form: the assertion is not merely imprecise, it can be flatly false,
and the row that disproves it is three lines below it in the same file.

**MEASURED** (`scripts/release-gate.mjs:272-273`) — `verdict` collapses **two
different causes** into one string. It is `'BLOCKED'` when
`problems.length === 0 && unmet.length === 0` is false — that is, when a quality
stage failed, **or** when an owner input is unmet, with no way to tell which.

**MEASURED** (`scripts/release-gate.mjs:288-294`) — the headline paragraph is
emitted on `verdict === 'BLOCKED'` alone. It reads _"Every gate that could fail
on quality passed. What blocks the release is N owner inputs."_ It **never
consults `problems` or any `stage.ok`**.

**MEASURED** (`scripts/release-gate.mjs:302`) — the stage table immediately
below is rendered from `stage.ok`, and prefixes a failed stage with
`**FAILED** —`.

**INFERRED** — so whenever a quality stage fails while any owner input is unmet,
the report asserts that no quality gate failed and then tabulates the one that
did. Six inputs are unmet today, so the second condition is currently always
true: **any** quality failure lands in this state. The two texts cannot
disagree loudly enough to stop anything, because nothing compares them.

**MEASURED** — the terminal output is honest where the artefact is not.
`scripts/release-gate.mjs:369-372` prints `RELEASE GATE FAILED — N problem(s)`
and `:382` exits non-zero on `problems.length > 0`. The defect is confined to
the generated document — which is the half that gets committed, and the half the
owner reads.

**OBSERVED, not committed** — on 2026-09-04 a gate run against `b33d52a` left a
regenerated `docs/release-gate.md` in the working tree, unstaged, in which the
`Dependency scan` stage reads `**FAILED** — FAILED` at 300.3s while the headline
paragraph above it still reads _"Every gate that could fail on quality passed."_
That regeneration is another lane's uncommitted work and is not part of this
record; it is cited only as the first observation of this failing in practice.
Whether that dependency-scan failure is a real high-or-critical advisory or a
network timeout is **not established here** and needs a gate re-run — a
release-adjacent action, not taken.

**INFERRED — why this outranks findings 1 to 4.** The other four either leave a
row correctly BLOCKED or make the explanation imprecise. This one lets the
artefact state the opposite of a measured result. A reader who trusts the
headline stops at "the only problem is owner inputs" and never reaches the
table, which is precisely the reading the headline was written to produce.
